# Reference Design Context

This glossary defines the language used while turning user-provided source material into a production-ready reference package. It contains no implementation procedure.

## Terms

**Source Subject** — The person, creature, object, or design whose identity must be preserved.

**Production Context** — The approved statement of intended asset identity, scale, mandatory features, assumptions, and forbidden redesigns.

**Reference Visual** — The approved multi-view Minecraft/Blockbench cuboid depiction that owns visible silhouette, proportions, pose, markings, and construction appearance.

**Golden Sample** — A quality and presentation exemplar. It supplies construction language, camera, layout, orientation, and technical hierarchy; it never supplies the new asset's identity.

**Reference Contract** — The human-readable and executable constraints derived from Production Context and Reference Visual.

**Reference Package** — The complete approved handoff consumed by Asset Production: Production Context, one Reference Visual, stage guidance, executable manifest, validation contract, and handoff metadata.

**Reference Candidate** — A package or visual that has not yet passed the required approval and blocking QA.

**Blocking QA** — Internal verification that prevents an invalid Reference Candidate from being presented as approval-ready.

**Reference Approval** — A user decision that accepts Production Context or Reference Visual. It is distinct from downstream production-stage reviews.

**Subject Clarification** — A question needed to resolve a high-impact fact about the Source Subject that is not visible or safely inferable.

**Reference Conflict** — A contradiction between approved Reference Design artifacts that cannot be resolved without reopening Reference Design authority.
