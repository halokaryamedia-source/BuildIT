# Blockbench MCP Core App Tool Contract

This is the BuildIT-side contract for Blockbench MCP tools.

The MCP Blockbench core app is the source of truth. BuildIT adapts to the core app through:

```txt
apps/engine/src/mcp/mcp-tool-name-mapping.ts
apps/engine/src/mcp/mcp-argument-shape-adapter.ts
apps/engine/src/mcp/mcp-action-schema-matcher.ts
```

## Required canonical tools

### `create_project`

Purpose:

```txt
Create or prepare a Blockbench project for the generated model.
```

Canonical arguments:

```json
{
  "name": "Project Name",
  "format": "bedrock_block"
}
```

Accepted BuildIT formats:

```txt
bedrock
bedrock_block
```

### `place_cube`

Purpose:

```txt
Place cube elements into Blockbench.
```

Canonical batch arguments generated by BuildIT:

```json
{
  "group": "body",
  "batchIndex": 0,
  "batchCount": 1,
  "elements": [
    {
      "name": "body_core",
      "group": "body",
      "from": [-4, 0, -2],
      "to": [4, 16, 2],
      "size": [8, 16, 4],
      "center": [0, 8, 0],
      "material": "main_material"
    }
  ]
}
```

Adaptation behavior:

- If the core app supports batch fields such as `elements`, `cubes`, or `boxes`, BuildIT keeps a batch payload.
- If the core app schema only supports a single cube payload, BuildIT expands the batch into one `place_cube` call per cube.
- If the core app expects a wrapper field such as `cube`, `box`, or `element`, BuildIT wraps each cube into that field.
- If the core app expects top-level cube fields such as `name`, `from`, `to`, `position`, `dimensions`, or `size`, BuildIT flattens each cube into top-level arguments.

### `capture_screenshot`

Purpose:

```txt
Capture the current Blockbench viewport or project preview.
```

Canonical arguments:

```json
{}
```

Expected result:

```txt
A data URL that starts with data:image/
```

BuildIT treats missing image data as a required result validation failure.

## Optional canonical tools

### `add_group`

Purpose:

```txt
Create a named model group or bone/container in Blockbench when the core app exposes a dedicated group tool.
```

Canonical arguments:

```json
{
  "name": "body",
  "origin": [0, 12, 0]
}
```

`add_group` is optional because some core app implementations can infer or create grouping from cube placement.

### `export_project`

Purpose:

```txt
Export or save the current Blockbench project.
```

Canonical arguments:

```json
{
  "name": "Project Name",
  "format": "bedrock_block"
}
```

Expected result:

```txt
A path-like value is preferred.
```

Export is optional. Missing export support or incomplete export metadata should not fail the whole job.

## Tool name adaptation

BuildIT resolves real core app tools in this order:

```txt
canonical exact match
alias match
normalized alias match
semantic match using tool name, description, and schema keys
```

This lets BuildIT adapt to the core app without requiring the core app to rename tools for BuildIT.

## Real core app compatibility process

When testing with `achmadawdi/mcp-blockbench`:

1. Run a BuildIT job with Blockbench MCP connected.
2. Open `mcp_tool_schema.json`.
3. Check real tool names.
4. Open `mcp_tool_name_mapping.json`.
5. Confirm all required canonical tools resolved.
6. Open `mcp_argument_shape_adaptation.json`.
7. Confirm arguments match real core app schema.
8. Open `mcp_action_schema_match.json`.
9. Confirm no required schema errors remain.
10. Open `mcp_execution_plan.json`.
11. Confirm final payload is what the core app expects.
